Deep dive · Aug 2026

LoveNeverDies

TL;DR A ten-day hackathon build for a Bavarian Ministry of Justice challenge. It's an installable PWA that walks bereaved families through German inheritance deadlines, and the server stores only ciphertext. The crypto is hybrid post-quantum, backed by 133 database-level test files.

Architecture

  • Each device generates ML-KEM-768+X25519 and ML-DSA-65+Ed25519 keypairs as non-extractable keys.
  • Key hierarchy: the device key unwraps the case key, which unwraps a per-item data key (AES-256-GCM). Private items and the vault get separate keys.
  • Writes queue in IndexedDB offline, then land as ciphertext in Supabase Postgres behind row-level security. Clerk issues the JWTs.
  • Sync checks a case version and fetches deltas past a watermark, triggered by a realtime "doorbell" with 30 s polling as fallback.
  • Device pairing uses an 8-character code plus a spoken 6-digit check derived from both public keys.

Key decisions

Hybrid KEM and signatures
Breaking one algorithm is not enough to break the scheme. Trade-off: 64 extra bytes per signature.
Per-item data keys
Key rotation re-wraps 32-byte keys instead of re-encrypting payloads: kilobytes instead of hundreds of megabytes.
Vault opens on proof of reconstruction
The vault key is Shamir-split across relatives (k = ⌈2n/3⌉ of n). A release counter could be tricked by a validly signed but bogus share, so proof of reconstruction is required instead.
No recovery phrase
Keeps the threat model simple for non-technical users. Trade-off: losing your only device means waiting for a relative to re-grant access.

Hard parts

  • Concurrent key rotation: a 2-minute row-locked lease plus compare-and-swap on the key generation.
  • bigserial was rejected for sync ordering because it can commit out of order. It was replaced by a per-case counter under row lock, plus a trigger that forbids un-deleting tombstones.

Numbers

  • 141node legal decision tree, 80 outcomes
  • 133Vitest files against 20 real Postgres migrations (PGlite/WASM)
  • 5multi-user Playwright E2E specs
  • 611probate courts mapped from 10,813 postcodes

Deep dive · 2026

SchafPlay

TL;DR Bavarian Schafkopf with serverless peer-to-peer multiplayer: two devices connect directly over WebRTC, with no backend at all. It's an offline-first PWA, live as v1.0.0, with a seeded Playwright suite in CI.

Architecture

  • The host creates the WebRTC offer, then minifies, deflates and base64url-encodes it into a compact invite code.
  • The guest receives it by paste, QR or link and returns a reply code; accepting it opens the data channel.
  • A single processAction entry point drives the engine; AI moves take the same validation path as humans.
  • Before anything leaves the host, redactStateFor replaces other hands with placeholders and hides the partner until revealed.
  • Games are recorded to IndexedDB for trick-by-trick replay analysis.

Key decisions

No signalling server, no STUN
Zero infrastructure and nothing to operate or pay for. It's LAN-first by design, with Tailscale documented for remote play.
Host-authoritative engine, one redaction boundary
The host even overwrites the guest's player ID, so nothing from the wire is trusted.
Minify SDP before deflate
Only per-session entropy (ICE credentials, DTLS fingerprint, candidates) is kept; everything else is regenerated on decode, which keeps codes short enough for QR.
One source of legality
rules.ts is the only place rules are decided, shared by the engine, UI and AI.

Hard parts

  • A dependency-free seeded shuffle (mulberry32 + Fisher–Yates) lets Playwright precompute identical deals in Node.
  • Every inbound string path is sanitized against a hostile host, and a data-channel heartbeat detects dead links.

Numbers

  • 17Playwright spec files, ~62 E2E tests, run on every push
  • 0servers: GitHub Pages hosts static files only
  • v1.0.0released and deployed via GitHub Actions

Deep dive · Bachelor thesis · 2024

Learning-Based Inverse Kinematics

TL;DR A quantitative comparison of learned IK solvers for 2- and 3-DOF planar arms. A plain MLP predicting angles directly solved 100% of 10,000 test problems within 0.01 tolerance, across 5 seeded runs, with the fastest inference (~155 µs). It beat every LSTM and probabilistic variant tested.

Results (5 runs, 10,000 test problems, accuracy within 0.01)

Model2-DOF3-DOFInference
Direct MLP100.0%100.0%154 / 157 µs
Two-peak Normal99.94%99.72%269 / 337 µs
Normal + LSTM99.96%93.25%474 / 526 µs
Two-peak LSTM67.71%92.99%366 / 514 µs
Normal (manual reparam.)97.5%75.59%321 / 372 µs
Beta5.19%8.48%207 / 257 µs

Key decisions

Loss through differentiable forward kinematics
The network is trained on end-effector distance to the goal, so no ground-truth joint angles are needed.
Geometry as an input
DH parameters are part of the input, so one model handles random arms instead of a single fixed robot.
sin/cos angle encoding
Each joint is predicted as (sin, cos) and converted with atan2, avoiding wrap-around at ±π.
Honest comparison
The MLP won on accuracy and inference time. It did not win on training time (~579 s vs 248–378 s for some variants).

Hard parts

  • IK is multimodal (elbow up or down), which motivated two-peak output distributions.
  • Some probabilistic heads collapsed: the Beta head reached only 5–8%.
  • Hydra configs, Optuna search (best MLP: 2048-256-2048, Adam, batch 512), W&B tracking and bootstrapped summaries, plus a PPO baseline in Stable-Baselines3.
